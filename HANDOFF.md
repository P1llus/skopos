# Agent handoff — schema redesign loop

You are one agent in a sequence of agents executing the schema
redesign planned in `SCHEMA_DESIGN.md`. The redesign collapses six
parallel reference grammars in the IR down to one rooted-path
grammar, deletes a handful of redundant constructs, and rewrites
every template / doc / test to match.

This file is **rolling**: the top half is constant (read it on every
handoff). The bottom half — "Current task" — is rewritten by the
outgoing agent each time control passes. After you finish your task,
you overwrite the "Current task" section with the next task and a
short status update.

---

## Constants (read first, every time)

### What you're working on

The master plan is in `SCHEMA_DESIGN.md`. **Read it before doing
anything else**, including the slice table, the §1 target design,
and the §4 rules of engagement. Every slice is scoped in §2 with an
effort estimate, the surfaces it touches, the slices it depends on,
and a "completes when" gate.

Repository layout:

- `schema/` — the Go IR (Doc, Value, Predicate, Path, validator,
  codec). No runtime dependency.
- `client/` — the in-process runner that consumes `*schema.Doc`.
- `templates/*.yml` — bundled example specs; each one is loaded,
  validated, and round-tripped in tests.
- `cmd/skopos/` — the CLI binary. Has `testdata/*.txt` golden files
  exercising every template.
- `docs/` — human-readable references. `schema-reference.md` is
  generated by `tools/gen-schema-doc`.
- `internal/testserver/` — stub HTTP server used by integration
  tests.

### Rules of engagement

These mirror `SCHEMA_DESIGN.md` §4. Re-read them on every handoff:

1. **No backwards compatibility goal.** Each slice's first commit
   bumps wire shape / templates / goldens / docs in lockstep with
   the code. Don't try to maintain dual paths.
2. **One slice = one self-contained landing.** `go test ./...` must
   be green at the end of every slice. Don't leave half-renamed
   schema lying around between slices.
3. **Validation errors name the new shape.** Every parse-time /
   validate-time error message points at the new form. If you delete
   a field, the error for "you used the old field" mentions the
   replacement.
4. **Codec round-trip stays byte-stable.** Existing fixtures in
   `schema/fixtures_test.go` cover this; if you change a field's
   YAML name, regenerate or rewrite the fixture in the same commit.
5. **Templates regenerate with their code change, not after.**
   `cmd/skopos/testdata/*.txt` goldens regenerate via
   `go test ./cmd/skopos -update` (or the project's equivalent
   refresh flag — check `cmd/skopos/testdata/README` or run a single
   golden test with `-v` to see the path). Confirm before relying on
   the flag name.
6. **Secret propagation is sacred.** Whenever you change `Value`,
   audit `schema.IsSecret(d, v)` and `predicateContainsSecret(d, p)`
   in `schema/value.go` to make sure every reachable Ref still
   propagates the secret marker.
7. **`ir_version` lives at `"1"` from slice 1 onwards.** Slice 1 is
   purely additive and stays on `"1"`. No release has been done yet so we can still use `"1"` for the wire-format identifier. The constant lives in `schema/doc.go` (`IRVersion`).

### Standard pre-flight (do this every task)

```sh
git status                 # confirm a clean baseline; only the
                           # SCHEMA_DESIGN.md / HANDOFF.md edits should
                           # be uncommitted at the start of a slice
go build ./...
go test ./...              # baseline must be green BEFORE you start
```

### Standard "I'm done" gate (do this every task)

```sh
go build ./...
go test ./...                  # entire test tree green
go vet ./...
go run ./tools/gen-schema-doc -check   # only if your slice touched
                                       # exported schema types
```

Plus a manual sanity check: pick any template that exercises the
shape your slice changed, run

```sh
go run ./cmd/skopos validate -i templates/<template>.yml
```

and `go run ./cmd/skopos run -i templates/<template>.yml --once`
against the test server (`go run ./cmd/testserver` in a separate
terminal). The latter is a smoke test that confirms the runtime path
still resolves correctly.

### How to communicate progress

When you finish your task:

1. **Update `SCHEMA_DESIGN.md` §5 (Progress log).** Add a row for the
   slice you completed: slice number, today's date, a one-line
   outcome, and the commit / PR reference.
2. **Note any divergences from the plan.** If the plan turned out to
   be wrong (a field couldn't be deleted cleanly, a slice had to
   absorb work the plan put in a later slice, etc.), edit the
   relevant slice in `SCHEMA_DESIGN.md` §2 to reflect what actually
   happened — and call it out at the top of your "next handoff"
   section so the next agent doesn't re-read a stale plan.
3. **Rewrite the "Current task" section of THIS file** for the next
   agent. Use the template at the bottom of this file. Include any
   carry-over notes the next agent needs (test failures you
   deliberately left for them, fixtures you partially regenerated,
   etc.).
4. **Commit your changes.** One commit per slice is fine; multiple
   commits are also fine as long as the slice is logically
   self-contained. **Do not push** unless the user explicitly asks
   you to.

### How to ask for help

If you hit a design ambiguity that `SCHEMA_DESIGN.md` doesn't
resolve, **stop and ask the human**. Don't guess — the whole point
of the plan is to keep the agents aligned. Examples of "ask first"
moments:

- A slice's intended renaming collides with an unrelated existing
  field.
- A doc example demonstrates a pattern that's hard to express in the
  new grammar (and might suggest the plan needs a tweak).
- The test infrastructure has a hidden assumption the slice would
  break.

## Current task

> **For the outgoing agent:** rewrite this section before you hand
> off. Use the template at the bottom of this file.

### Slice number and title

**Slice 7 — Move expiry slots out of `cursor`.**

### What this slice does

Today the OAuth2 token cache and the per-request `requests[].cache`
both stash their "fresh until" timestamp at a framework-internal
key inside the `cursor` namespace (the leading `__` prefix marks
it as "do not touch from a template"). That leaks a runtime
implementation detail into the author-facing snapshot — `cursor.*`
is supposed to be the template's pagination/progress state and
nothing else. Slice 7 moves the expiry slot into the `state`
namespace, paired with the token it describes, and auto-registers
it as a runtime-mutability `string` field so the validator and
the snapshot codec treat it as first-class state. After this
slice the only keys under `cursor.*` are the template-visible
pagination / progress signals.

See `SCHEMA_DESIGN.md` §1.9 for the target shape and §2 Slice 7
for the implementation outline.

### Surfaces this slice touches

- `client/oauth2.go` — every read/write against
  `cursor[__oauth2_<store_in>_expires_at]` moves to
  `state[<store_in>_expires_at]`. The cache helper that calls
  through (look for the helper that resolves the expiry slot
  given a `TokenCache.StoreIn`) needs to switch namespace. Audit
  the file for both "token store" and "expiry store" call sites.
- `client/requestcache.go` — same rename for the per-request
  token cache. The `RequestCache` helper computes the expiry slot
  key from `store_in`; flip the namespace there.
- `client/state.go` — the auto-registration helper that today
  injects the `__*_expires_at` slot into the cursor schema needs
  to register it under the state schema instead (string,
  runtime). The cursor schema's per-strategy slot table loses the
  expiry slots entirely; the state schema picks them up.
- `client/runner.go` — if there's any seed/snapshot wiring that
  pre-populates the cursor with `__*_expires_at` keys it needs to
  move to the state init path.
- `schema/schema.go` / `schema/validate.go` — `cursorSchema`
  registers any `cursor.__*` slots; remove those registrations.
  The validator's `cache.store_in` collision check today rejects
  declaring the token state name twice; extend it to also reject
  an author declaring `<store_in>_expires_at` in `state.fields`
  when a cache block is present. The state-schema builder
  (`stateSchema`) gains an auto-registration arm that adds
  `<store_in>_expires_at` as runtime / string for every
  `requests[].cache.store_in` and every `auth.oauth2.cache.store_in`
  (whichever the rest of the codebase already centralises through).
- `schema/fixtures_test.go` — any inline YAML or struct literal
  that reads `cursor.__…` flips to `state.<store_in>_expires_at`.
  Add a focused `TestSliceSevenExpirySlotsMoved` mirroring
  TestSliceFive / TestSliceSix: positive — a `cache: {store_in:
  oauth2_token}` block validates with `state.oauth2_token_expires_at`
  auto-registered; negative — declaring
  `state.fields.oauth2_token_expires_at` alongside the same cache
  is a validator collision; negative — `cursor.__oauth2_token_expires_at`
  is no longer a valid ref (the validator reports "unknown cursor
  field").
- `client/requestcache_test.go` / `client/auth_test.go` — every
  test that pokes at `__*_expires_at` flips to the new state
  slot name. Run after the schema move to confirm the runtime
  reads + writes consistently.
- `cmd/skopos/testdata/state/*.json` (or wherever the snapshot
  goldens live — `grep -rn '__.*expires_at' cmd/skopos/testdata/`
  to find them) — regenerate any snapshot golden that captured
  a token-cache expiry under the old key.
- `schema/testdata/oauth2_relay.yml` — if it pins the expiry
  key explicitly, flip; otherwise the change is internal.
- `docs/schema-reference.md` regenerates if any exported struct
  or YAML tag changes. The broader runtime-doc cleanup (stores,
  runtime, snapshot table) is still slice 8 — keep `docs/`
  changes to the gen-schema-doc output in this commit.

### Acceptance criteria

1. No `cursor.__*` keys remain in `client/`, `schema/`,
   templates, fixtures, or goldens. `grep -rn 'cursor\.__\|"__.*expires_at"'`
   returns nothing under those trees.
2. `state.<store_in>_expires_at` is auto-registered as a runtime
   `string` state field whenever an OAuth2 or request cache block
   declares `store_in: <name>`. A test pins the auto-registration.
3. The validator's `cache.store_in` collision check also rejects
   an author-declared `state.fields.<store_in>_expires_at` (or
   equivalent — the rejection message names the colliding cache).
4. `go test ./...` green; `go vet ./...` clean;
   `go run ./tools/gen-schema-doc -check` green;
   `go test -tags integration ./cmd/skopos/...` green.
5. Smoke-test `oauth2_client_credentials`, `oauth2_relay`, and
   `session_login_cached` (the templates that exercise a token
   cache) end-to-end against the testserver. `snapshot.json` (or
   whatever the runtime persists) shows the expiry under
   `state.*` not `cursor.*`.
6. `ir_version` stays `"1"`.

### Out of scope for this slice

- Do not touch any author-facing cursor slot — only the
  framework-internal `__*_expires_at` keys move. `cursor.token`,
  `cursor.scroll_id`, `cursor.page`, etc. all stay where they are.
- Do not rewrite `docs/runtime.md` / `docs/stores.md` beyond what
  the rename forces — broader doc cleanup is slice 8.
- Do not collapse `state` and `cursor` — slice 9 (deferred).

If any of those become unavoidable, **stop and ask**.
